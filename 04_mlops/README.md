# MLOps: From Notebook to Production

MLOps (Machine Learning Operations) is the discipline of deploying, serving, monitoring, and maintaining machine learning models in production. It's the bridge between a trained model in a Jupyter Notebook and a live, reliable system that real users depend on.

## A Note on Scope

MLOps is a **massive field** — and increasingly a **profession of its own**. In large organizations, dedicated ML Engineers and MLOps Engineers spend their entire careers building and maintaining the infrastructure that keeps models running: feature stores, model registries, experiment tracking platforms, distributed training pipelines, Kubernetes orchestration, A/B testing frameworks, and more.

This pillar does **not** attempt to cover all of that. This repository is a **Data Science** learning resource, and its focus must stay there.

Instead, this pillar covers **freelance-level MLOps knowledge** — the practical minimum a data scientist needs to take a trained model from a notebook and deliver it as a working product to a client. You won't learn how to manage a fleet of GPU clusters, but you *will* learn how to:

- Save a model and load it in a different environment
- Wrap it in an API that anyone can call
- Package it in a Docker container that runs identically everywhere
- Deploy it to the cloud with a single command
- Build a visual dashboard for non-technical stakeholders
- Monitor it and know when it needs retraining

This keeps the repository **complete** — a data scientist who finishes this pillar can deliver end-to-end — without drifting into ML Engineering territory.

## The Iris Pipeline: A Single Thread Through Every Section

Rather than building disconnected examples, this entire pillar follows a **single model** through the full MLOps lifecycle: an Iris classification Pipeline (StandardScaler + RandomForestClassifier) trained in Section 01 and carried all the way to a deployed, monitored, dashboard-equipped product in Section 06.

```
Train and save the model     → 01_model_persistence
Serve it via an API          → 02_api_development
Package it with Docker       → 03_containerization
Deploy it to the cloud       → 04_cloud_deployment
Build a visual front-end     → 05_interactive_dashboards
Monitor and maintain it      → 06_monitoring_and_maintenance
```

## Sections

### [01 — Model Persistence](./01_model_persistence/)
Save and load trained models using pickle, joblib, and ONNX. Learn why you should always persist the full Pipeline (not just the model) and save metadata alongside the artifact.

### [02 — API Development](./02_api_development/)
Build a FastAPI application that serves predictions from the saved Pipeline. Define input/output schemas with Pydantic, handle batch predictions, and explore auto-generated Swagger documentation.

### [03 — Containerization](./03_containerization/)
Package the API into a Docker container so it runs identically on any machine. Write a production Dockerfile, set up Docker Compose, and learn layer caching and image optimization.

### [04 — Cloud Deployment](./04_cloud_deployment/)
Deploy the containerized API to the internet using a PaaS platform (Railway). Automate testing and deployment with GitHub Actions CI/CD. Compare deployment options across platforms.

### [05 — Interactive Dashboards](./05_interactive_dashboards/)
Build a Streamlit dashboard with sliders, live predictions, confidence charts, and feature context visualizations. Turn the model into something non-technical stakeholders can interact with directly.

### [06 — Monitoring and Maintenance](./06_monitoring_and_maintenance/)
Add structured logging and error handling to the API. Understand data drift and concept drift. Learn when and how to retrain a model — scheduled, triggered, and the practical reality of keeping models fresh.

### [07 - Architecture](./07_architecture/)
Knowing *what* the blocks are is not enough; you need to know *how* they fit together so that the result is maintainable, testable, and adaptable to change. That's what software architecture is about.
